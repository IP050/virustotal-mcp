# 0.9.9

Hosted attachment submission uses the client-neutral `submit_attachment` tool.
Its descriptor requires only a public HTTPS `download_url` for the original file;
optional `file_id`, `file_name` and `mime_type` fields and `openai/fileParams`
metadata preserve compatibility with existing host file objects. Embedders must
use `bind_attachment_submissions` and `vt_mcp.attachments`; the previous attachment
tool and binder names are removed. Hosts remain responsible for authentication,
file-write permission and bounded, safe downloads. Native attachment transfer
still depends on the client and is not claimed for unverified hosts.

Submission guidance requires the user's explicit request. Missing file, URL,
domain and IP reports remain unknown and give read-only recovery guidance.
Standard sharing disclosures, sensitive-content safeguards, quota handling and
uncertain-submission recovery remain in place. Every tool now includes its
human-readable title in annotations as well as its top-level metadata.

Credential-like filenames are denied before file access or attachment download,
including Windows drive-relative names. Attachment denials return the closed
`sensitive_file` error with human-review guidance. Optional receipt/analysis
arguments accept JSON `null` consistently with their schemas while still requiring
exactly one non-null receipt identifier.

The bundled Claude Code plugin is version 0.1.5. Its skill and the Antigravity and
portable threat-intelligence skills require explicit submission requests and
retain the existing sharing, permission and recovery safeguards.
